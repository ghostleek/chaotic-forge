# PC-04 — Give each participant a clear room and card interface

**Status:** Local issue draft; no GitHub issue/PR created, verified, or assigned.
**Proposed accountable owner / implementer:** Kahhow. **Reviewer:** Lance, independent of implementation.

## Outcome

Each participant can join the room from their browser, see the current phase and their role, select an initial concept variant, and understand when they may add a later mechanic. Connection or command failures remain recoverable and visible.

Read [PRD](../../PRD.md), [PLAN](../../PLAN.md), [QUALITY](../../QUALITY.md), [AGENTS](../../AGENTS.md), PC-01's accepted contract, and the provenance/state findings in [prior review](../../archive/2026-09-13-mechanic-lab/mechanic-forge-pr-review.md).

## Scope and file ownership

Allowed: `lib/party-forge/client/room-client.ts`, `lib/party-forge/client/use-room.ts`, `components/party-forge/lobby.tsx`, `components/party-forge/card-picker.tsx`, `components/party-forge/recipe-summary.tsx`, `components/party-forge/room-status.tsx`, corresponding scoped CSS modules, `tests/party-client.test.mjs`, and `tests/fixtures/party-ui/**`. Kahhow owns these files. Shared protocol, runtime, API, global styles, package files, and final route composition remain outside this packet.

The first demo presents three visible FPS/Zombies/Cooking slots with two supported variants each. Each person contributes one selection; the result explains all three contributions. Display authored-demo origin without narrating implementation internals unnecessarily. Do not introduce the rejected generic base-game picker or advertise unsupported unknown cards as playable.

Implement the room client against the real command/snapshot protocol, including capability handling, polling lifecycle, stale revisions, idempotent retry, focus, loading/error/rejoin states, and server-confirmed selections. The UI can explain edit eligibility but cannot grant it. Keep current playable build visible when a new resolution fails. Show capped/unavailable cards and Pass explicitly.

Fixtures may drive tests and isolated development only. There is no production fake room, fake participant result, or success state after a failed request. Build reusable components without making an incomplete route the public entry point.
