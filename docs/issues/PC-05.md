## Outcome

Each browser can play the resolved FPS/zombie/cooking game: aim, move, interact with cooking objectives, face enemies, and finish a scored trial. A 2.5D raycast presentation is acceptable when aiming and the game interactions are real.

Read [PRD](../../PRD.md), [PLAN](../../PLAN.md), [QUALITY](../../QUALITY.md), [AGENTS](../../AGENTS.md), PC-02's accepted runtime/snapshot contract, and the single-runtime/input findings in [prior review](../../archive/2026-09-13-mechanic-lab/mechanic-forge-pr-review.md). The ModeShift import is visual/architectural reference, not proof this gameplay exists.

## Scope and file ownership

Allowed: `components/party-forge/game-viewport.tsx`, `components/party-forge/trial-hud.tsx`, `components/party-forge/use-trial-controller.ts`, `lib/party-forge/presentation/**`, `lib/party-forge/client/trial-input.ts`, related scoped CSS modules, `public/party-forge/kitchen-chaos-v1/**`, `docs/party-forge-assets.md`, `tests/party-input.test.mjs`, and `tests/browser/party-viewport.spec.ts`. Kahhow owns rendering/input/art files. Lance retains runtime/score/contract ownership. Request an explicit handoff for shared changes; do not implement a second scoring engine in the view.

Use one mounted runtime owner, one ticking lifecycle, and a bounded fixed-step input trace. Render only authoritative snapshots. Clear held input on focus/pointer-lock loss while the scored clock continues; scored trials never pause. A surviving client may submit its retained trace within the original deadline plus 30-second transport grace, never extra playtime. Refresh/crash losing the trace makes the attempt incomplete; only an explicit whole-round abort/retry with a new round ID starts another scored attempt. Input capture must record actual gameplay without frame-rate-dependent scoring.

Support the first demo's desktop keyboard/mouse controls, clear objective, remaining time, action feedback, result state, and accessible surrounding UI. Pointer-lock failure needs a usable documented aiming fallback. Every selected mechanic must have a visible consequence; do not substitute a screenshot, scripted score, or cinematic camera for playable first-person behavior. Keep authored demo provenance clear.

Assets are optional polish, but any accepted asset requires an immutable version/path and source/license or generation provenance. Runtime code and art versions used by saved manifests must remain available after later deploys.
